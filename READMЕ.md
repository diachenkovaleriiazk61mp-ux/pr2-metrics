## Запуск у Windows

Потрібні Docker Desktop (режим Linux containers) і Python 3.10–3.13. Відкрий PowerShell у папці проєкту й виконай:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Після цього доступні:

- API: http://localhost:18081/healthz
- Prometheus Targets: http://localhost:19090/targets

Щоб запустити інше число екземплярів, додай параметр `-Replicas`:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Replicas 4
```

У Targets мають з’явитися чотири цілі `web` зі станом UP. За бажанням збережи скриншот цієї сторінки в `figures/targets-4.png`, поки запущено чотири екземпляри. Стан цілей і так записується у відповідь API Targets.

На Linux і macOS: `sh start.sh` або `sh start.sh 4`.

Пароль до бази створюється автоматично і зберігається в `.env`. Якщо файл уже є, пароль у ньому не змінюється. Не змінюй пароль після того, як база вже створена. Порти другої роботи 18081 і 19090, а томи починаються з `vaccinations-pr2`, тому з першою роботою нічого не перетинається.

## Вимірювання

Виконай на комп’ютері з Docker:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lab.txt
.\.venv\Scripts\python.exe scripts/experiment.py
```

Перед стартом зупини контейнери першої лабораторної (`vaccinations-pr1`) і закрий зайві програми. Генератор і Docker працюють на одному комп’ютері, тому будь-яке стороннє навантаження псує результати.

Що робить скрипт:

1. Калібрує генератор через `/noop`.
2. Запускає прогони на 1, 2, 3 і 4 екземплярах.
3. Зберігає метрики, таблиці й графіки.
4. Перевіряє SIGTERM.

Це займає багато часу, бо прогін триває, доки сервіс не перестане встигати.

### Як влаштовано навантаження

- Генератор працює у двох процесах з асинхронним клієнтом, кожен бере свою частину розкладу.
- Спочатку 10 с прогріву на 200 rps, далі сходинки по 20 с: 200, 400, 600 rps і так далі.
- Для кожної сходинки враховуються останні 15 с.
- Прогін зупиняється, коли дві сходинки поспіль нижчі за 90% заданої інтенсивності, або після сходинки, що досягла межі генератора G.
- Тайм-аут запиту 5 с, затримка рахується від запланованого моменту відправки.
- Сценарій: читання одного запису. У всіх прогонах читається запис 101, один із ста доданих перед серією.

### Калібрування

У калібрування є запобіжна межа 20000 rps. Якщо її досягнуто, а насичення не настало, це значення **не можна брати за G**. Тоді запусти ще раз з більшою межею:

```powershell
.\.venv\Scripts\python.exe scripts/experiment.py --safety-max-rate 40000
```

### Коли генератор не справляється

- Якщо точка N=1 обмежена генератором, або після виключення таких точок лишається менше двох придатних N>1, скрипт повторює серію з 0.75 CPU на web. Пам’ять і пул не змінюються. Обидві серії зберігаються окремо, а обрану видно в `results/selected-series.json`.
- Якщо генератор відстає від розкладу, скрипт зберігає діагностику й завершується з помилкою. Перевіряється, що розпочато не менше 98% запланованих запитів і p95 затримки відправки не більший за 100 мс. Такі дані в розрахунок USL не йдуть. Якщо й з меншим CPU даних замало, потрібен швидший генератор.

### Повторні запуски

Перед новою повною серією старі `results/` переміщуються в `history/`. Базу й том Prometheus скрипт не видаляє. У кожній серії додається ще 100 записів, тому після повторного запуску в таблиці можуть лишитися записи попередньої серії. Про це треба згадати в описі умов у звіті.

## Що з’являється після запуску

| Файл | Що в ньому |
|---|---|
| `results/noop.json` | запити калібрування |
| `results/cpu-*/run-N.json` | запити, посекундні результати, незавершені запити |
| `results/cpu-*/prometheus-N.json` | часові ряди й бакети за сходинками |
| `results/cpu-*/run-N.resources.jsonl` | `docker stats`, CPU і RSS генератора, CPU хоста |
| `results/cpu-*/targets-N.json` | стан цілей Prometheus |
| `results/cpu-*/lb-N.log` | лог балансувальника лише за час відповідного прогону |
| `results/graceful-check.json` | код завершення і помилки навколо зупинки |
| `RESULTS.md` | таблиці, підстановки у формули, графіки |
| `figures/` | всі графіки |

Щоб заново порахувати таблиці й графіки зі збережених файлів:

```powershell
.\.venv\Scripts\python.exe scripts/analyze.py
```

Скрипт оновлює `RESULTS.md` і графіки. Пояснення й висновки в `REPORT.md` після нового запуску треба поправити вручну.

## Перевірки коду

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тест SIGTERM працює тільки на Linux, на Windows його пропущено. Справжня перевірка через `docker stop` входить у повну серію.

## Захист від переповнення черги

На кожному екземплярі одночасно працює не більше 64 CRUD-запитів (`MAX_INFLIGHT_REQUESTS`). Якщо всі місця зайняті, новий запит одразу отримує 503 з полем `capacity`, і це рахується помилкою. Генератор при цьому не зупиняється.

Ще кілька деталей:

- `/metrics`, `/livez` і `/healthz` цю чергу не займають.
- Nginx не повторює 503 на іншому екземплярі, щоб відмова не збільшувала навантаження.
- Пул бази лишається на 15 з’єднань.

Щоб вікно PowerShell не закрилося після завершення або помилки, запускай так:

```powershell
powershell -NoExit -ExecutionPolicy Bypass -File .\run-lab.ps1
```

## Публікація на GitHub

1. Створи порожній публічний репозиторій **pr2-metrics**.
2. У корені проєкту підготуй папку `submission`:

   ```powershell
   .\.venv\Scripts\python.exe scripts/package_submission.py
   ```

3. Завантаж у репозиторій **вміст** папки `submission`, а не саму папку. У вебінтерфейсі зручно додавати файли й папки кількома порціями, зберігаючи структуру.

У репозиторії мають бути `scripts/`, `tests/`, `results/` і `figures/`. Файли `.env`, `.venv`, `.git`, `history/` і ZIP не завантажуються: скрипт їх пропускає сам.

Файл `results/noop.json` важить приблизно 206 МБ, тому скрипт ділить його на стиснені частини по 50000 записів у `results/noop-raw/`. Самі записи не змінюються. Решта полів і контрольна сума SHA256 початкового файлу лежать у `metadata.json`. Локальний `results/noop.json` лишається на місці.

Щоб відновити великий файл із завантаженої копії, виконай `python scripts/restore_raw.py`. Скрипт перевіряє SHA256 і не перезаписує наявний `noop.json`. Якщо треба створити `submission` ще раз, спочатку перейменуй або видали стару папку.

Зупинити контейнери без втрати результатів можна командою `docker compose down`. Команда `docker compose down -v` видаляє базу й часові ряди Prometheus, тому використовуй її тільки після експорту метрик і побудови графіків.
